# 在线 AI（可选）

知语默认**完全在本机运行**：推荐、翻译、语音都用随程序发布的本地模型。本页描述的是一层
**可选的**在线能力——把输入法正在处理的那段文字交给一个 API 去处理，**默认关闭**，只有用户在
设置里打开、并且**逐个功能**打开之后才会联网。

> 隐私：一旦打开，被处理的那段文字（例如划词翻译里选中的文字）会离开本机、发送到所选服务商。
> 相关的隐私说明见 [privacy.md](privacy.md)。

## 配置（`%USERPROFILE%\zhiyu\default.json` 的 `ai` 段）

| 字段 | 默认 | 说明 |
|------|------|------|
| `ai.enabled` | `false` | **唯一的开关**（1.7.64 起）：关着时行为与没有这个功能时完全一致，也不会有任何文字离开本机；打开后下面勾选的功能才走线上，**线上失败一律自动回退**（划词翻译用本机翻译模型，语音退回识别原文，动作给出原因）。设置页那个勾选框和「在线 AI 开关键」写的是同一项 |
| `ai.provider` | `deepseek` | 内置提供方表的 id（见 `shared/include/cxxime/ai_client.h` 的 `table()`，约 30 家：deepseek / openai / anthropic / google / kimi / glm / qwen / siliconflow / hunyuan / minimax / 小米 / groq / openrouter / mistral / ollama …） |
| `ai.base_url` | `""` | 空 = 用该提供方自带的地址；也可填自建/代理地址 |
| `ai.model` | `""` | 空 = 用该提供方自带的默认模型 |
| `ai.reasoning_effort` | `""` | 推理档位；空 = 不发这个字段 |
| `ai.timeout_ms` | `8000` | 单次请求超时（1000–120000） |
| `ai.keys` | `[]` | **多把** API 密钥，**DPAPI（当前用户）加密后的 base64**，不是明文。一把被拒（401/429）自动换下一把 |
| `ai.use_for.*` | 全 `false` | 哪些功能允许走线上：`translate`（划词翻译）/ `selection`（选中文字的 AI 动作）/ `voice`（语音识别后处理） |
| `ai.action_key` | `""` | 动作菜单键：**按一下就弹出菜单**（见下节）。可以是 `"F6"`、`"Ctrl+K"`，或轻按修饰键 `"RShift"` / `"Shift"`（任一侧）/ `"Ctrl"`。空 = 关闭 |
| `ai.action_keys` | `{}` | 某个动作自己的键：`{"proofread": "F7"}`，按它直跑该动作、不弹菜单（写法同上） |
| `ai.language_key` | `""` | **语言列表键**：按一下就弹出 `\fy` 那张 12 种语言的列表（写法同 `ai.action_key`，含轻按修饰键）。空 = 关闭 |
| `ai.voice_action_key` | `""` | **语音处理键**：按一下就弹出语音识别后处理的列表（纠错 / 提问），选中即写进 `ai.voice_polish_action` 并把 `ai.use_for.voice` 打开（写法同上）。空 = 关闭 |
| `ai.translate_language` | `en` | **走线上时中文译成哪种语言**（12 种代码；默认与 `translate` 动作的 `languages` 首项一致）：「翻译」动作和划词翻译键（Ctrl+C+C）都按它，别的语言一律译成中文。设置页有下拉可选，输入框里用 `\fy` 换。**离线模型不看它**，只看「学习」页那两行 |
| `ai.enable_key` | `""` | **在线 AI 开关键**：按一下就弹出「线上（开）/ 线上（关）」，选中即写进 `ai.enabled`——与设置页那个勾选框是同一项（写法同 `ai.action_key`，含轻按修饰键）。空 = 关闭 |
| `ai.search_provider` | `tavily` | 联网搜索用哪家：`tavily` 或 `deepseek`（DeepSeek 自己的搜索接口，用同一把平台 key）。设置页那一行是个下拉 |
| `ai.search_keys` | `{}` | 每家的密钥（**DPAPI 加密后的 base64**，与 `ai.keys_by_provider` 同路子）：`{"tavily": "…", "deepseek": "…"}`。**DeepSeek 留空 = 用 AI 里那把 DeepSeek 密钥**（同一个平台的 key），Tavily 没有就搜不了 |
| `ai.search_enabled` | `false` | **联网搜索的开关**：打开后「提问」会先搜再答（见下节）。设置页那个勾选框与搜索开关键写的是同一项 |
| `ai.search_key` | `""` | **搜索开关键**：按一下就弹出四行「搜索（开）/ 搜索（关）/ Tavily / DeepSeek」（当前在用的那家标着「（当前）」），选中即写进配置（写法同上）。空 = 关闭 |
| `ai.action_disabled` | `{}` | 不在菜单里列出的动作：`{"summarize": true}`。没写的都列出 |
| `ai.voice_polish_action` | `proofread` | 语音识别后处理用哪个动作（`data/ai_actions.json` 的 id）；**空 = 不做这一层**。设置页「语音识别后处理」那一行右侧的下拉给**纠错 / 提问 / 不使用**三项（它同时就是这个用途的开关） |

密钥不写明文：设置页会把输入的密钥用 `CryptProtectData` 加密后存进 `ai.keys`，只有同一台机器的
同一个用户能解回来（`shared/src/ai_client.cc` 的 `protect_secret` / `unprotect_secret`）。

## 反斜杠命令在英文（ASCII）状态下也能用（1.7.57）

`\` 是**命令前缀**，不只是中文输入时才有：**英文状态下**（轻按 Shift 切到的直接英文）打 `\fy` 一样弹出语言列表，
`\bd` 一样列出标点候选（数字键选），与中文状态完全一致。三条规则：

- **两个反斜杠 = 一个字面反斜杠**：`\\` 上屏一个 `\`（中文状态下 `\\` 仍是 `\` 的中文标点 `、`，未变）；
- **命令接不下去就是文字**：`\` 后面若是什么命令都接不上的字母，输入法**把打过的按键原样上屏**（大小写保留）——
  `C:\\Users` 这样打路径不会丢字，也不会有候选窗口挂着不走；连 `\` 后面直接跟空格（或逗号这类字符）也照样原样上屏；
- **候选键归候选**：像 `\bd` 这样**有候选**时，数字、空格、Tab、方向键、翻页键仍然是在选候选（`\bd` 再按 `1` 上屏 `、`）。

实现：`engine/src/engine.cc` 的 `english_symbol_text_fallback()`（判断"这个键之后命令还接得下去吗"，`SymbolTable::has_code_prefix()`），
`engine/src/symbol_processor.cc` 在英文状态下**保留大小写**（候选/命令的匹配一律折叠大小写）。

## 一个修饰键只有一个含义（1.7.57）

`ascii_composer.switch_key` 里默认把 `Shift_L`/`Shift_R` 都绑成了"轻按切中英"。当用户把**同一个修饰键**又设为 AI 键
（`ai.action_key` / `ai.action_keys` 里某一项 / `ai.language_key`）时，**同一次轻按会触发两件事**：输入模式切了、菜单却没出来
（"右 Shift 在浏览器里变成了中英切换"就是这么来的）。现在引擎在加载配置时会**把被 AI 用掉的那个修饰键的 switch_key 槽位置成
`noop`** —— AI 键的那个含义胜出（`engine/src/config.cc`，加载 `ai` 段之后）。实测（Chrome）：**右 Shift 轻按 = 弹菜单、且不再切中英；
左 Shift 轻按 = 照旧切中英**。

## 支持的协议

`shared/include/cxxime/ai_client.h` 的 `Protocol`：

- `openai-completions` — `POST {base}/chat/completions`（deepseek、openai、kimi、glm、qwen、ollama…）
- `anthropic-messages` — `POST {base}/v1/messages`（claude、minimax、kimi-coding…）
- `google-generative-ai` — `POST {base}/models/{model}:generateContent`
- `mistral-conversations` — `POST {base}/v1/chat/completions`

网络走系统 **WinHTTP**、JSON 用仓库已有的 **nlohmann**，没有引入任何新的第三方依赖。

## 语音识别后处理（`ai.use_for.voice`）

在「AI」页把「语音识别后处理」那一行选成**纠错**或**提问**之后（下拉的第三项是「不使用」，也就是不做这一层），
语音识别出的文字**先交给 `ai.voice_polish_action` 指定的那个动作过一遍**（默认 `proofread`，也就是「纠错」），
拿回来的文字才是上屏的内容。触发方式、录音、悬浮窗、按键
流程**一个字没动**：语音键照旧开始/结束录音，客户端照旧每 100 ms 问一次状态——只是「识别中」会多停一会儿
（就是这次请求的时间，受 `ai.timeout_ms` 限制），然后上屏的是处理后的文字。

- **哪个动作**：`ai.voice_polish_action`（`%USERPROFILE%\zhiyu\default.json` 的 `ai` 段），值是
  `data/ai_actions.json` 里某个动作的 id，**默认 `proofread`（纠错）**；**留空 = 这一层不做**（识别文字原样
  上屏，用途开关留着）。想让语音过去「润色」就把这一项改成 `polish`。
  **设置页给三项**（「AI」页那一行右侧的下拉）：**纠错 / 提问 / 不使用**——前两项就是 `proofread` 与 `ask`，
  选任一项即打开这个用途，「不使用」把它关掉（手上的动作留着）。
- **「提问」（`ai.voice_polish_action = "ask"`）**：识别出来的那句话**当成问题**发给 AI，**上屏的是 AI 的回答**
  （识别原文不上屏）。它用的就是「选中文字的 AI 动作」里那一项 `ask`（提示词、上限 8000 字都一样），所以回答
  跟着问题的语言走。失败时照旧退回识别原文（也就是问题本身）。
- **顺手切换**：按一下「AI」页的**「语音处理键」**（`ai.voice_action_key`，写法同动作菜单键 / 语言列表键），
  光标处会弹出**「纠错 / 提问 / 不使用」三行**的小列表（与设置页那个下拉同一组选项、同一个顺序）——
  数字键、方向键、空格或回车执行，Esc 取消，也可以鼠标点；**选中即写进配置**：选动作就打开「语音识别后处理」
  （否则选了不生效），选「不使用」就关掉它。
  它就是动作菜单那套窗口，不用先进设置页；列表里的名字取自 `data/ai_actions.json`。
- **联网搜索也管语音**：`ai.voice_polish_action = "ask"` 时，**用的就是「AI」页那套搜索设置**（同一个开关、
  同一个来源、同一把密钥）——识别出来的那句话先拿去搜一页结果再交给 AI，见「联网搜索」一节
  （两条路共用 `cxxime::ai::with_web_search()`）。
- **插在哪儿**：`server/src/voice_service.cc` 的 `finish_recording()` 里，`tidy()` 之后、把文字存进
  `text_` 之前（那是语音自己的工作线程，占线也不影响录音与按键）。
- **任何一步不顺都退回识别原文**：总开关没开 / 没勾这个用途 / `ai.voice_polish_action` 空着或写了不存在的
  id / 没有密钥 / 请求失败或超时 / 识别文字超过该动作的 `max_input_chars`（8000）—— 宁可原样上屏，也不会把
  用户口述的内容弄丢。
- **用的是同一个动作定义**：提示词与上限都来自 `data/ai_actions.json` 那一项（改文件即生效），所以这一层的
  规矩与「选中文字 → 同一动作」完全一致。

## 选中文字的 AI 动作

选中一段文字，**按一下「动作菜单键」**即可（默认不设；可以是 `F6` 这类单键、`Ctrl+K` 这类组合，或
**轻按**右 Shift）。选中内容由输入法自己读取——TSF 读不到的程序里（老式 Win32 编辑框等）它会替你按一次
`Ctrl+C` 再取剪贴板——所以**不必自己先按 Ctrl+C**。光标处弹出这个菜单：

```
 1. 润色
 2. 纠错
 3. 改写
```

（菜单是候选窗口的一种用法，但没有拼音行、也没有翻页箭头；顺序就是 `ai_actions.json` 里的顺序，
被 `ai.action_disabled` 关掉的不列出。）

按 `1`～`9` 或方向键选择、`回车`或`空格`执行、`Esc`取消；**也可以直接用鼠标点**那一行（悬停会高亮；菜单窗口
不抢焦点，点它不会把光标从输入框里挪走）。方向键**四向都算移动**：`↑`/`←` 上一项、`↓`/`→` 下一项
（`Tab` 也向后一项）——菜单横排竖排都顺手，因为候选窗口的排法（`layout`）用户可能改过。
另外可以给某个动作配一个**自己的键**（`ai.action_keys`），按它就直跑那个动作、不弹菜单。

**要处理的内容是"三级来源"**，按这个顺序找，找到就用（`_read_selected_text`，docs 见下）：

1. **有选区** → 用选区（与原来看不出区别）；
2. **没选中** → 用**光标这一行从头到光标的那一段**——输入法会先把这段**选中**（你一眼能看到要处理什么），
   **并把它放进剪贴板**（等于替你复制了一份，但由输入法直接写入，不会给程序塞按键事件）；
3. **前两级都没有**（光标这一行前面没字，或程序不让输入法读它的文字）→ 用**剪贴板里的内容**——
   也就是**你之前 `Ctrl+C` 复制的东西**：在空输入框里、或者在不给文字的程序里，
   按动作键/菜单键照样能用刚才复制的那一段。

所以：

- **剪贴板排在最后**：它永远不会盖掉你光标处的选区或这一行——"我明明要处理这一行，它却去处理了别的东西"
  这种情况不会发生；而且走到第 3 级时，处理的那段文字就显示在窗口里（"正在润色…"下面那一行），你随时能看出用的是哪一份；
- 结果的落点与选区一致：替换类动作替换选区/那一行（**光标右边的文字不动**），摘要写在选区之后；
  第 3 级时没有选区，结果就写在光标处（也就是这一行的开头）；
- 单行输入框（聊天框、搜索框）里第 2 级取的是**光标之前**的内容，不是整个框；
- **密码框一律不动**：既不读它，也不会拿剪贴板来顶替（第 3 级在私密字段里被禁用）；
- 三级都取不到时，光标处说明原因——**按键从不毫无动静**，否则看起来就像键坏了；
- 程序**读不到文字**、而且它自己复制回来的**正好是光标这一行**时（Sublime 这类"没选中就复制整行"的编辑器）：答案**替换这一行**。
  **依次试三种办法，每一种都用"复制回来的内容是不是那一行（选区的副本不带换行，程序自己复制整行带换行）"来验证**：
  ① **`Home` + 让 TSF 从光标起选"整行那么长"**（`select_length_at_caret()`：这一行有多长我们早已知道——就是程序刚复制给我们的那份——
  所以先发一个纯 `Home`（**不认合成 Shift 的程序也认它**）把光标放到行首，再 `ShiftEnd(+N)` + `SetSelection`。
  **不可读的文档也试**，因为"它的文本存储认不认这个选区"正是要问的事；光标在行中、行尾都选得对）；
  ② 不行才发按键 **`Home` + `Shift+End`**（**一个键一个键地发**：`Home` 一下，按住 `Shift` 点 `End`，松开 `Shift`；
  键带扫描码、每步之间停 120 ms 并跑消息泵，让程序按完一个再做下一个）；③ 再不行用 **`Ctrl+L`**（这类编辑器绑的"选中整行"）。
  三者都用同一次 **`Ctrl+C`** 取回内容比对，每次的结果记在 `ai_ui line_select how=… selected=…` 里——
  对得上才粘贴；对不上（有的程序不认合成的 `Shift+End`，它 Ctrl+C 复制整行只是因为"没选中"）就**只显示答案、不粘贴**，
  绝不让答案盖到光标处别的文字上（`select_line_with_keys()` / `select_and_copy_line()`，docs/ai.md）
- 程序**读不到文字**时（老式 Win32 编辑框、Sublime 这类自绘编辑器、提权窗口）：输入法先发 **`WM_COPY` 消息**
  请它自己复制（消息不进程序的输入流，经典编辑框认它、也不会像注入按键那样引起它的输入上下文抖动），
  不行才注入一次 `Ctrl+C`（那些按键带标记，输入法自己的按键处理会忽略它们），并且**最多等 300 ms**（边等边看剪贴板序号）。
  **如果连复制都没成功，就不再拿剪贴板里的旧内容顶上**，而是明确说「没取到选中的内容：请先自己按一次 Ctrl+C 再按这个键」
  —— 过去那条"静默回退到剪贴板"正是"有时处理了你看不见的文字"的来源。
  **例外**：划词翻译键（`Ctrl+C+C`）的**第一下本来就是你自己按的复制**，那份剪贴板内容就是你要处理的那段，所以它照旧使用。

> 隐私：因为是你按下键之后才复制、只处理刚复制的那一份，所以不会把剪贴板里遗留的旧内容（比如早先复制的
> 口令）送去处理。开着在线 AI 时离开本机的，也只是这一行或这段选区。

> 提示：这条意味着「没选中 → 用剪贴板」是**目的性读取**，剪贴板里若留着别的什么（早先复制的链接、
> 密码管理器里的口令），按一次动作键就会把它送去处理 —— 开着在线 AI 时它还会离开本机。
> 想要更保险可以只认「刚复制不久的」内容，需要的话再加。

**默认的六个动作**（`data/ai_actions.json`，顺序就是菜单顺序）：

| id | 名字 | 结果 | 输入上限 | 说明 |
|---|---|---|---|---|
| `translate` | 翻译 | 替换选区 | 8000 字 | **带语言列表**（12 种，见下）：**中文**译成下拉选的那个语言，**其它语言一律译成中文**；**走划词翻译那条服务**（线上优先、失败回退离线模型），所以 Ctrl+C+C 会用到的模型它也用得上 |
| `polish` | 润色 | 替换选区 | 8000 字 | 口语→书面、去赘字 |
| `proofread` | 纠错 | 替换选区 | 8000 字 | 只改错别字/标点/中英之间空格 |
| `rewrite` | 改写 | 替换选区 | 8000 字 | 换一种说法，长度与语气不变 |
| `summarize` | 摘要 | **插到选区下方**（原文不动） | 32000 字 | 同语言概括成一小段 |
| `ask` | 提问 | **插到选区下方**（原文不动） | 8000 字 | 把选中的那句话**当成问题**，AI 直接回答；回答用问题本身的语言。和「摘要」一样只往输入框里插结果，需要自己配一个键（`ai.action_keys` 的 `ask`）或从菜单里选 |

- **翻译的语言与方向**：设置页「AI 动作」卡里，`translate` 那一行右侧的下拉选 **12 种**语言之一（英、中、日、韩、法、德、西、俄、越、葡、意、阿）。方向按**源语言**分：
  - 选中的是**中文** → 译成下拉里那个语言（线上）；下线（离线模型）则按「学习」页那两行走；
  - 选中的是**其它语言** → 一律译成**中文**（线上）；
  - **离线模型**（线上失败时的回退）**总是**按「学习」页的候选翻译两行取目标 —— 与 Ctrl+C+C 完全一致。
  **离线模型只覆盖 9 种**（中英日韩法德西俄越），葡/意/阿只有线上可用。
- **在输入框里换语言**：打 **`\fy`**（`\` 就是符号输入的前缀，命令优先于符号名），**候选条里列出的就是那 12 种语言**
  —— 它就是一次普通的符号组字，只不过候选不是符号而是语言名。选法也完全是原来那套：数字键、方向键 + 空格/
  回车、Tab 循环、`,` `.` 翻页、鼠标点选；**选中的语言存进 `ai.translate_language`**（与设置页那个下拉是同一项），
  **不上屏任何文字**（这条命令只是改设置），组字随之结束。
  实现：引擎识别这条命令（`engine/src/symbol_processor.cc`）后**不结束组字**，由翻译那一步
  （`Engine::translate_composition` → `Engine::ai_language_result`）用语言列表替换符号表；每个候选带一个
  `AiLanguageAction`（`engine/include/cxxime/candidate_selection.h`），选中时不走"上屏文字"那条路，而是走
  `Context::choose_ai_language()` 记下语言并结束组字（`Engine::dispatch_candidate_selection`）。服务端在这次按键/
  这次点选之后把它取走（`Engine::take_ai_language_choice()`），以合并补丁写进配置
  （`ConfigWriteCoordinator::enqueue_patch`，与「英文模式」等同类；`server/src/session_manager.cc` 的
  `persist_ai_language`）。所以这一功能**没有自己的窗口、没有自己的按键、没有额外的 IPC 命令**。
  名字取 `shared/src/ai_actions.cc` 的 `ai_language_label()`（中/英两种，与 `ai_action_label` 同规则）。
- **也可以配一个键直接弹它**：`ai.language_key`（设置页「动作菜单键」下面那行「语言列表键」）。按它就等于**替你打了 `\fy`**——
  输入法把这三个按键送给引擎（`TextService::_open_language_list`，用 `_modifierOverride` 保证不带修饰键），
  于是列表、键位、选法全都与手打命令一模一样；组合成词中（正在打拼音时）不触发，因为那时 `\fy` 只会是标点。
  **它与 `ai.action_key` 写法完全一致**（单键/组合/轻按修饰键）。
- **动作定义是数据**：`data/ai_actions.json`（随安装包发布，也可以自己改）。每条 =
  `id` + 名字（中/英）+ `prompt`（system 提示词，用户消息就是选中的原文）+
  `insert`（`replace` 替换选中文字，可 `Ctrl+Z` 一步撤销；`below` 写在选中文字**下方**、自成一行
  ——摘要用的就是它；`preview` 只显示）+
  `max_input_chars`（**字符数**，超过就只处理前面这么多，并明确提示；两侧都按字符数算——
  中文 8000 字是 24000 字节，按字节算会把它误判成超限）+ `timeout_ms`（**当前未生效**：请求用的是
  `ai.timeout_ms`）+
  `languages`（可选：带它就表示"这个动作要选一种语言"，翻译用的就是它，且不写 `prompt`——
  翻译的提示词是程序内置的那一句，与 Ctrl+C+C 一致）。加一个动作不用改程序。
- **只走线上 AI**：需要 `ai.enabled` + `ai.use_for.selection` + 有密钥。没配好时窗口会直接说明
  原因（例如「没有配置 API 密钥（设置 → AI）」），而不是悄悄什么都不做。
- **执行中**：窗口显示「正在润色…」，超时或失败显示原因；`Esc` 可取消。
  拿不到结果时窗口**一定**有收尾：服务端给的原因、或「无法完成：服务没有返回结果」——不会把
  「正在…」留在屏幕上。发送失败（和后台服务的连接断了）同样会说明。
- **长选区**：超过 `translate.max_selection_chars`（默认 32000 字）或该动作的 `max_input_chars`
  时，只处理前面那一段并提示「（只处理了前 N 字）」；要**替换**选区的动作此时改成**只显示**——免得把
  没处理的部分丢了（写在下方的那种不受影响，它本来就不动原文，提示作为最后一行跟着写进去）。
- **撤销：完全交给程序自己的 `Ctrl+Z`**。输入法**不碰撤销**——它不拦截 `Ctrl+Z`（带 Ctrl/Alt 的组合键一律放行给程序，
  `engine/src/engine.cc` 里就写着这条规则），也没有自己的撤销栈。替换选中的答案（`insert: replace`）送回的方式是
  **粘贴**：答案放进剪贴板、再送一次 `Ctrl+V`，由程序用它自己的选区完成替换——程序记下的是一次**普通编辑**，
  `Ctrl+Z` 一步收回；写在下方的那种（摘要 + 提示行）是 TSF 直接写入，也是一次编辑，一并收回
  ——**程序读不到文字时**（Sublime 这类，TSF 写不进去）改用程序自己的按键：`End`（光标那一行被程序复制
  回来时，光标在行中）或 `Right`（选区还在，它把光标收到选区末尾、不动原文），然后粘贴"换行 + 答案"，
  也是程序自己的一次普通编辑。
  **为什么替换不走 TSF 直接写入**：实测（Win11 Notepad）TSF 写入**不进程序的撤销栈**——`Ctrl+Z` 跳过它、去撤销上一步
  （当初把原文粘进去的那次粘贴），整个文档被清空，再按多少次都回不来。这不是这一条路独有：用输入法**自己打字**（组字
  提交）覆盖同一个选区，`Ctrl+Z` 同样回不来，Ctrl+Y 反而把输入法的字找回来——Notepad 对"输入法在选区上写入"的撤销
  整合本身就是坏的。粘贴则各处都对：同一份文档手工 `Ctrl+V` 覆盖后 `Ctrl+Z` 原文完好，Sublime Text 本来就是走粘贴，
  VS Code 与 Notepad 实测一次 `Ctrl+Z` 都能还原。代价是答案会留在剪贴板上（读的时候原文也已经放在那里了）。
- 实现：`shared/src/ai_actions.cc`（读动作）、`shared/src/ai_client.cc`（`run_action`，含去引号/
  去「以下是…」这类包装）、`server/src/ai_action_service.cc`（后台线程跑、结果留内存供分块取回）、
  `tsf/src/text_service_translate.cpp`（菜单与写回）。

## 联网搜索（只有「提问」用）

「AI」页「在线 AI」那一行下面就是搜索那一块：**「搜索」开关行**（勾选框「启用联网搜索」+ 右边的「搜索开关键」）
和**「来源」行**（下拉 **Tavily / DeepSeek** + 该来源的密钥框 + 「获取 API Key」链接）。密钥与 API 密钥一样
**DPAPI 加密**后存进 `ai.search_keys`，不写明文。

- **两家**：`tavily`（[tavily.com](https://app.tavily.com/home)，注册就能复制，免费额度 1000 credits）与
  `deepseek`（DeepSeek 自己的搜索接口，**用同一把平台 key**——所以 DeepSeek 那一栏**留空就用 AI 里那把
  DeepSeek 密钥**，也可以单独填一把覆盖它）。链接与说明跟着来源换。
- **只给「提问」用**：`ask` 动作——**两条路都算**：选中文字（菜单第 6 项 / 自己配的键）与**语音识别后处理选「提问」**
  （识别出来的那句话就是问题）——在发请求前，
  先把**那句话本身**当作查询发出去——Tavily 是 `POST https://api.tavily.com/search`（`max_results` 5、
  `search_depth: basic`，一次搜索算一个 credit）；DeepSeek 是 `POST https://api.deepseek.com/v1/tools/search`
  （`count` 5、`need_content: false`，用它的 `snippet` + `summary`；地址跟着 AI 页的地址走，填了代理就用代理）。
  拿回来的标题 / 地址 / 摘要按 `[1] …` 编号拼成上下文，连同问题一起交给 AI；提示词里同时要求"依据这些结果
  回答，并在末尾列出用到的来源地址"。润色 / 纠错 / 改写 / 摘要 / 翻译**都不搜**。
- **开关**：`ai.search_enabled`。设置页那个勾选框「启用联网搜索」，以及它右边的**「搜索开关键」**
  （`ai.search_key`）写的是同一项。默认关。开关键按一下弹出**四行**：
  `1 搜索（开）` `2 搜索（关）` `3 Tavily` `4 DeepSeek`——后两行是换来源（当前在用的那家标着「（当前）」），
  选中即写进 `ai.search_provider` 并**顺手打开搜索**。
- **搜不到不失败**：没有密钥 / 开关关着 / 请求失败 / 结果为空 —— 一律**照旧直接回答**（搜索只是加料，
  不是前提）；密钥被拒这类原因由服务商返回（`http_request` 把 401/403 变成"密钥被拒"）。
- 实现：`shared/src/ai_client.cc` 的 `web_search()` / `search_available()`（复用同一套 WinHTTP + nlohmann +
  DPAPI），调用点在 `server/src/ai_action_service.cc` 的 `do_action()`（只对 `action->id == "ask"`）。

### 长文本怎么走 IPC

选中的文字和 AI 的回答都可能很长，而 IPC 的普通字段只有 4096 字节。短文本仍走老路
（`TRANSLATE_SELECTION` / `TRANSLATE_STATUS`，一字未改）；超过一个字段时改用四个追加式命令
（`shared/include/cxxime/ipc_protocol.h`）：

| 命令 | 用途 |
|---|---|
| `TEXT_UPLOAD_BEGIN` (37) | 开始上传：`key_code`=用途、`search_query`=动作 id、`modifiers`=总字节数 |
| `TEXT_UPLOAD_CHUNK` (38) | `candidate_index`=偏移、`translate_text`=一块（≤4095 字节） |
| `TEXT_RESULT_POLL` (39) | 状态 + `text_result_bytes`=已就绪字节数 |
| `TEXT_RESULT_READ` (40) | 按偏移取回一块 |

这样收发都没有 4096 字节的天花板，也没有结构体改动（`IPCRequest`/`IPCResponse` 的
baseline 与 static_assert 全部保持）。**顺带修掉了划词翻译的两个老问题**：选区超过 1000 字
以前会被静默砍掉、并且开着「直接上屏」时会把整段选区替换成那一小段的译文（后面的原文就丢了）；
现在超长会提示且不替换（`docs/settings-guide.md` 的 `translate.max_selection_chars`）。

## 设置界面

设置程序里的「AI」页（`settings/editor_ai_panel.cc`，也可用 `zhiyu-settings.exe --panel ai` 直接打开）：

- **在线 AI**：总开关（唯一的开关），**右边就是「在线 AI 开关键」**（`ai.enable_key`，按一下弹出
  「线上（开）/ 线上（关）」），以及一行「当前使用：地址 · 模型」——地址或模型留空时用的就是服务商自己的
- **搜索**（就在「在线 AI」那一行下面）：勾选框「启用联网搜索」+ 右边的「搜索开关键」（`ai.search_key`）；
  再下面一行是**「来源」**：下拉 Tavily / DeepSeek + 该来源的密钥框 + 框右边的「获取 API Key」链接
  （Tavily 与 DeepSeek 各一个链接，显示当前来源那个），密钥框下面一行是随来源变的说明
- **服务商**：内置表里的下拉（约 30 家）
- **接口地址 / 模型**：留空即用服务商自带的，也可以填自建或代理
- **API 密钥**：密码框；填入后点「确定/应用」即加密保存（DPAPI，仅本机本用户可解）并清空输入框，
  下方显示已存几把
- **超时（毫秒）**、**哪些功能可以用**（三个用途开关）、**测试**（对一句中文跑一次真实请求并显示结果）

密钥、开关都写进 `default.json` 的 `ai` 段（见上表），所以换机器要重新填密钥。

## 命令行自查

`zhiyu-server.exe --ai-test --key <key> [--provider id] [--base-url url] [--model name] [--text "文本"] [--out 结果文件]`
走的就是输入法用的那条链路（DPAPI 往返 → 提供方表 → WinHTTP → 协议 → 解析），用来确认密钥/网络通不通。

AI 动作也可以这样自查（`--data` 指向带 `ai_actions.json` 的 data 目录；打印结果与耗时）：

```
zhiyu-server.exe --ai-action --action proofread --key <key> --text "我觉得这个方按可以" --out r.txt
```
