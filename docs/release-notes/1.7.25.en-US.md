- **Much faster long-pinyin composition**: the decoder model read every character written so far again for each new one. The same weights now also come as two graphs that keep a KV cache (`laya_decoder_memory` / `laya_decoder_step`), so each character costs only its own work and the earlier ones are reused. Upstream measured (CPU, 11-16 characters in full pinyin, one whole query): **134 -> 79 ms** median, **227 -> 126 ms** P95; the first candidate is unchanged (3130/3270), accuracy is unchanged, and fp32 output matches the old path exactly. The longer the input, the more it saves
- New setting `laya.decoder_cache` (on by default): used when those two graphs are in the model folder; off goes back to the old algorithm
