- **Fix: in Sublime Text and other classic editors the action runs and its result is typed, but the input method's own little window (正在润色… / the action menu) is never seen.** The reason: reading the text means copying it for you, and such a program — especially **running as administrator** — re-activates its input context over that, so the input method's edit target changes and the tidy-up that follows takes the window down the moment it appears. A browser never does that, which is why it always worked there
- **The change**: those windows now have a **0.9 second grace** — a target change in that moment no longer takes them away — and a diagnostic entry (`ai_ui`) is left behind, so if another program has the same habit the log will name it
- Worth knowing: in such a program "the caret's line" cannot be read at all (it keeps its text to itself), so the clipboard is what those keys use there — press `Ctrl+C` once before the action key; a selection still works as usual
