- **Change: a program that cannot be read is asked to copy by message first (`WM_COPY`)**, and only falls back to a `Ctrl+C` of ours when the message changes nothing. The log showed why: such a program — an elevated editor especially — re-activates its input context over **keys we inject**, and that can wipe the **selection**, which is how the wrong text ends up copied and how a later paste has no selection left to replace. `WM_COPY` is a message, not input: a classic edit box honours it and nothing of ours enters the program's input stream
- **Better diagnostics**: the answer window now also records **how big it actually laid out** and how long its text is — so "`visible=1` but not seen" can be told apart as "nothing was drawn" or "it was placed/covered wrong"
