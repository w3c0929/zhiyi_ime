- **修（关键）：在 Sublime 这类程序里，我们的复制请求一直"慢一拍"**。实测查明：注入的 `Ctrl+C` **本身是有效的**（由外部进程注入，测试中剪贴板序号 232→238 ✓），但我们的读取是在**程序自己的线程上**跑的（TSF 按键处理就在那个线程），所以那三个按键只是**排进队列**，要等我们的处理函数返回后才被处理 ✗ —— 而我们就在处理函数里干等剪贴板 → 永远等不到 ✗。这解释了此前**全部**现象：为何你自己按 Ctrl+C 就管用（线程空闲、当场处理 ✓）、为何"时好时坏"（上一轮按下的复制被下一轮读到 = 慢一拍 ✓）
- **改法**：等待期间**把程序的消息跑起来**（消息泵，`wait_for_program_copy`），而不是干睡；等待时到达的按键算程序的（`_readingSource` 守卫），不再参与输入法的按键判定
- 现在这类程序里：**替你复制 → 等它真复制出来 → 用真复制出来的那份** ✓（不再是剪贴板里的旧内容）
