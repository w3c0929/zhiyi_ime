- **AI actions on the selected text (new)**: select some text and press the **action menu key** (`ai.action_key`: a plain key like `F6`, a chord like `Ctrl+K`, or a **tap** of right Shift) to open a menu right at the caret — polish / proofread / rewrite / summarize / translate. Pick with `1`-`9` or the arrows, run with `Enter`, cancel with `Esc`, or just **click the row** (the menu does not take focus, so clicking it does not move your caret out of the box). Any action can also have **a key of its own** (`ai.action_keys`, e.g. `{"proofread": "F7"}`) that runs it directly, without the menu. The actions and their prompts are **data** (`data/ai_actions.json`, yours to edit), and `ai.action_disabled` keeps one out of the menu. The input method reads the selection itself — **you do not press Ctrl+C first**
- **Which text an action works on (three tiers)**: ① a selection, if there is one; ② otherwise **the caret's line, from its start to the caret** (the input method **selects** that stretch first and puts it on the clipboard, so you can see what is being worked on); ③ otherwise **what you last copied**. The clipboard is always last, so it never displaces the selection or the line at your caret; **password fields are never touched** (not read, and the clipboard is not used in their place). In a program whose text cannot be read (classic Win32 edit boxes, self-drawn editors like Sublime Text, elevated windows) it first asks the program to copy with a `WM_COPY` message, injects a marked `Ctrl+C` only if that changes nothing, and **waits at most 300 ms**; if even that copy did not come it says "没取到选中的内容：请先自己按一次 Ctrl+C 再按这个键" instead of quietly working on the old clipboard. With nothing in any tier it says why, right at the caret — **a key never does nothing in silence**
- **Where the answer lands**: a replacing action replaces the selection (or that line) and leaves the text to its right alone, and undo is the program's own `Ctrl+Z` (see the fix below); a summary (`insert: below`) is written **under the selection, on a line of its own**. A selection longer than `translate.max_selection_chars` (32000 characters by default) or than the action's `max_input_chars` is only worked on up to that point, with a note saying so (**counted in characters** — 8000 Chinese characters are not mistaken for an oversized selection), and a replacing action is then shown instead, so the part that was not worked on is not thrown away
- **`\fy` changes the translation language (new)**: type `\fy` in the input box and the ordinary candidate bar lists 12 languages; picking one writes it into `ai.translate_language` and **commits no text**. A key can be bound to it (`ai.language_key`, taps included), which is the same as typing the command. This feature has **no window, no key and no IPC command of its own**
- **Voice post-processing (new)**: with `ai.use_for.voice` on, recognised speech goes through the action named by `ai.voice_polish_action` (proofread by default) before it is committed; the key, the recording and the floating window are untouched. If any step fails (the master switch off, the purpose off, no key, a timeout, over the action's limit) the **recognised text is committed unchanged** — what you dictated is never lost
- **A new AI page in Settings**: the master switch, the keys (stored encrypted per user with `CryptProtectData`, **never in the clear**), the action menu key, the language-list key, a switch per purpose (selection translation / AI actions on a selection / voice) and, per action, whether it is listed and its own key, plus the translation language
- **Fix: the answer takes one undo.** The answer used to be written back into the selection through TSF, and **some programs do not record such a write in their undo stack at all** — measured in Win11 Notepad: one `Ctrl+Z` **empties the whole document** (it undoes the earlier paste that put the text there instead) and no number of further presses brings it back; typing over the same selection with the input method's own composition fails the same way, so Notepad's undo of anything an input method writes is broken ✗
- The answer that replaces a selection is now **pasted back** (onto the clipboard, then one `Ctrl+V`, so the program replaces its own selection) — the delivery every program undoes in one step: Sublime Text always worked that way, Chrome restores the original text with a **single `Ctrl+Z`** (measured on 1.7.56), and a manual paste over the same text in Notepad undoes in one press ✓. The selection translation's direct insert (`translate.direct_insert`) uses the same delivery and is fixed with it
- **Fix: no more silent failures, and no window stuck on "正在…"**: nothing to work on, the server connection gone, or an answer that never came are all said at the caret; the waiting window no longer sits on "正在…" for ever
- **Fix: the window no longer moves about**: the progress/answer window is **placed once, when it first appears, and stays there**; its position is clamped into the monitor's work area (high DPI, several monitors, and programs like VS Code that report the caret in physical pixels), and it is put back when a program takes it down while the answer is being fetched
- **The packaging is fixed too**: in the first 1.7.56 package the programs still **carried 1.7.55 inside** (that build had not picked the new `VERSION` up, so nothing but the file the edit touched was rebuilt), which left Settings and Check for updates reporting a newer version for ever; `package_release.py` now checks the embedded version of every `zhiyu*` program in the package and **fails** when one does not match — the programs in this one all say 1.7.56
