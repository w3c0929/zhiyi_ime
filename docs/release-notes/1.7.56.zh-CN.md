- **选中文字的 AI 动作（新）**：选中一段文字，按一下**动作菜单键**（`ai.action_key`：可以是 `F6` 这类单键、`Ctrl+K` 这类组合，也可以**轻按**右 Shift）就地在光标处弹出菜单——润色 / 纠错 / 改写 / 摘要 / 翻译；按 `1`～`9` 或方向键选、`回车`执行、`Esc` 取消，**也可以直接用鼠标点**那一行（菜单不抢焦点，点它不会把光标从输入框里挪走）。每个动作还能配**自己的键**（`ai.action_keys`，如 `{"proofread": "F7"}`）按下去直跑、不弹菜单；动作清单与提示词是**数据**（`data/ai_actions.json`，可以自己改），`ai.action_disabled` 能把某个动作从菜单里收起来。选中内容由输入法自己读取——**不必自己先按 Ctrl+C**
- **它按哪段文字工作（三级来源）**：① 有选区 → 用选区；② 没选中 → 用**光标这一行从行首到光标**那一段（输入法会先把这段**选中**、并放进剪贴板，你一眼能看到正在处理的是什么）；③ 前两级都没有 → 用**剪贴板里你刚复制的那一份**。「剪贴板」永远排在最后，不会盖掉你光标处的选区或这一行；**密码框一律不动**（既不读它，也不拿剪贴板顶替）。程序**读不到文字**时（老式 Win32 编辑框、Sublime 这类自绘编辑器、提权窗口）：先发 `WM_COPY` 消息请它自己复制（消息不进程序的输入流），不行才注入一次带标记的 `Ctrl+C`（输入法自己的按键处理会忽略它们），**最多等 300 ms**；连复制都没成功就明确说「没取到选中的内容：请先自己按一次 Ctrl+C 再按这个键」，**不再拿剪贴板里的旧内容顶上**。三级都取不到时就地说明原因——**按键从不毫无动静**
- **结果的落点**：替换类动作**替换选区/那一行**（光标右边的文字不动），撤销交给程序自己的 `Ctrl+Z`（见下面那条修复）；摘要（`insert: below`）写在**选区下方、自成一行**。长选区超过 `translate.max_selection_chars`（默认 32000 字）或该动作的 `max_input_chars` 时**只处理前面一段并明确提示**（按**字符数**算——中文 8000 字不会被误判成超限），要替换的动作此时改成只显示，免得把没处理的部分丢掉
- **`\fy` 换翻译语言（新）**：输入框里打 `\fy`，用**普通候选条**列出 12 种语言，选中即写进 `ai.translate_language`、**不上屏任何文字**；也可以给 `ai.language_key` 绑一个键（含轻按修饰键），按它就等于替你打了这条命令。这一功能**没有自己的窗口、没有额外的按键、没有额外的 IPC 命令**
- **语音识别后处理（新）**：`ai.use_for.voice` 打开后，语音识别出的文字**先过一遍 `ai.voice_polish_action` 指定的动作**（默认「纠错」）再上屏；触发方式、录音、悬浮窗、按键流程一个字没动。任何一步不顺（总开关没开、没勾这个用途、没密钥、超时、超过该动作的上限）都**退回识别原文**，绝不把口述的内容弄丢
- **设置页新增「AI」页**：总开关、密钥（用 `CryptProtectData` 按当前用户加密后存储，**不写明文**）、动作菜单键、语言列表键、逐功能开关（划词翻译 / 选中动作 / 语音），以及每个动作的开关与独立键、翻译语言下拉
- **修：答案一步就能撤销**。之前把答案写回选区用的是 TSF 直接写入，**有些程序根本不把它记进撤销栈**——实测 Win11 Notepad：按一次 `Ctrl+Z` 会把**整个文档清空**（它去撤销了上一步"把原文粘进去"的那次粘贴），再按多少次都回不来；用输入法**自己打字**覆盖同一个选区也一样回不来，这是 Notepad 对"输入法写入"的撤销整合本身的毛病 ✗
- 现在替换选中的答案**改用粘贴送回**（答案放进剪贴板 + 一次 `Ctrl+V`，由程序用自己的选区完成替换）——这正是各家都能一步撤销的写法：Sublime Text 本来就这么送，Chrome 上实测（1.7.56）**一次 `Ctrl+Z` 原文完好回来**；Notepad 里对同一份文档手工粘贴覆盖后，一次 `Ctrl+Z` 同样能还原（它的 TSF 写入路径则不能）✓。划词翻译的「直接写入」（`translate.direct_insert`）走同一条路，一并修好
- **修：不再有静默失败，也不再有卡在「正在…」的窗口**：没有可处理的内容、与后台服务断开、服务没有返回结果，都会在光标处说明原因；等待窗口不会永远停在「正在…」
- **修：窗口不再乱动**：进度/答案窗口**只在第一次出现时定位、之后待在原地**；位置会夹进显示器工作区（高 DPI、多屏，以及 VS Code 这类按物理像素报光标的程序）；等待期间程序把窗口藏起来时会重新显示
- **顺带修好打包流程**：上一份 1.7.56 的安装包里，程序**内嵌的版本号还是 1.7.55**（那次构建没吃到新的 `VERSION`，除改动过的文件外都没有重编），设置页与「检查更新」因此会一直提示有新版本；现在 `package_release.py` 会核对包里每个 `zhiyu*` 程序的内嵌版本号，对不上就**直接失败**——本份包里的程序都是 1.7.56
